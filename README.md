GitHub Pages 发布静态活动信息，评分和看板使用独立云服务与 SQLite 数据库。前端零构建依赖，后端仅使用 Python 标准库。

## 本地预览

```sh
python -m http.server 4173 --bind 127.0.0.1
```

此命令只预览公开活动信息。完整平台需要 Python 3.11+：

```powershell
$env:GOTC_DATA_DIR = '.runtime/local-data'
$env:GOTC_PORT = '5274'
$env:GOTC_PUBLIC_ORIGIN = 'http://127.0.0.1:5274'
python -B server/app.py
```

打开 http://127.0.0.1:5274/gotc/ 。首次运行的管理码保存在指定数据目录的 `admin-access.txt`，不要提交或公开。提交到 `main` 后由 GitHub Actions 验证并发布官网；云端发布方式见 [部署说明](deploy/README.md)。

## 维护内容

- `index.html`：公开活动内容与日程。
- `styles.css`：响应式样式。
- `app.js`：日程切换、清单、复制链接与导航。
- `platform.html`、`platform.css`、`platform.js`：评审工作台、后台与进度页；`platform-admin.js` 提供数据管理界面。
- `server/app.py`：身份认证、评分、投票、SQLite 持久化与静态服务。
- `assets/`：活动现有主视觉和报名二维码。
- `downloads/`：日历与作品提交清单。

页面以 2026 年 10 月学校交流版为活动信息基础。原有六维专业评分、成绩看板和后台评分设置继续可用；独立的展示评审记录使用另一套轮次与数据，尚未接入新赛制的数值计算及晋级规则。现场细则、GOTC 详细场地和最终组织安排以主办方通知为准。旧 9 月活动的观众加分、后台、队伍及学生数据未接入本官网。

## 发布范围

仓库包含平台源码和公开活动素材，不包含聊天记录、报名数据、数据库、管理码、评委邀请码、API 密钥或内部方案文件。作品采用链接式提交，不上传文件；作品提交清单可公开查看。

新数据库初始无参赛队伍、评委或评审记录，原专业评分与新展示评审窗口均默认关闭。组织方先录入本届队伍、发放邀请码；专业评分直接使用原有工作台，独立展示记录另行配置本轮队伍和评委名单。成绩看板每 2 秒更新，大屏模式每 12 秒轮播 8 支队伍；展示记录进度单独展示，不计入专业成绩。

## 专业评分与成绩看板

`platform.html#judge` 保留原有六维评分：20、20、20、15、15、10 分，支持 0.1 分步长、草稿、正式提交、改分和回避。`#board` 显示达到人数门槛的专业均分、并列排名及独立观众票，也可切换大屏。后台保留专业 `scoringOpen`、最少评委数、成绩公开和原评分 CSV；观众投票另由 `votingOpen`、`votingDeadline` 控制，不随专业评分开关改变。

这些是已有的单阶段评分语义，并非新赛制的去极值、分赛道晋级或两阶段综合公式。新规则没有确定时，不替换或停用原评分功能。

## 作品提交

组织方先录入队伍，在后台的“作品提交管理”为每队生成独立提交码并单独发放，再打开作品提交窗口。提交码只显示一次；重发或停用会立即作废该队旧会话，保留已保存材料。没有公开注册，也不收集成员联系方式。

队伍在“作品提交”保存草稿，填写作品名与介绍、公开线上仓库主页与最终代码版本、README、许可证说明、展示材料、视频、来源与局限，以及演示链接或本地演示说明。草稿允许缺项，正式提交需要完整填写并确认自查。

请先将本地代码推送到公开仓库，再填写最终 commit。Gitee、GitCode、GitHub 和 GitLab 可粘贴同仓库的提交详情页链接，所有平台都可填写完整的 40 或 64 位哈希。页面摘要显示前 6 位。PPT 和视频各填一个分享链接，无需上传文件。许可证文件链接选填。所有链接必须为 HTTPS，外链可访问性、许可适用性、材料页数和视频时长由队伍自行检查。

草稿不覆盖评委可见的最近正式材料，再次正式提交才更新正式版本和公开作品名称。多人编辑遇到版本冲突时，输入会保留，可查看最新草稿后自行合并。平台保存字段和链接，外部链接内容仍可能改变，不提供内容存证。

作品提交开关独立于评分与投票，默认关闭、未设截止。后台截止时间按北京时间填写，服务器到点锁定；补交需管理员延长截止并重新开放。建议先关闭提交再评审。评委只读正式材料；后台可检查草稿和正式材料并单独导出提交 CSV，原评分导出保留。

旧数据库首次升级会在私有数据目录备份并事务迁移账号角色约束，保留原账号、会话、评分与投票。请保留持久化数据目录，不以删库方式升级。本功能不改变当前评分、排名或晋级算法。

保存、冲突、外链快照的最终含义，以及迁移演练、代码回退与数据恢复的区别，见 [作品提交上线与回退说明](docs/submission-release.md)。回退旧代码不会自动还原数据库；恢复旧备份则会舍弃备份之后的新写入，必须单独确认并保留当前数据。

## 展示与路演评审框架

展示与路演分别管理队伍、评委、轮次和窗口。组织方选择本轮队伍和评委、开放窗口，首次开放时冻结当时的队伍信息与正式项目材料。评委可保存观察意见草稿、提交正式定性记录、修改或回避；多人编辑通过版本检查防止静默覆盖。关闭或截止后只读，新建轮次保留旧轮次记录。

展示记录入口为 `platform.html#judge-exhibition`，路演记录入口为 `#judge-roadshow`；公开记录进度分别是 `#board-exhibition` 与 `#board-roadshow`，原 `#judge`、`#board` 继续用于专业评分和成绩。后台可以切换新记录阶段。路演队伍由组织方手动选择，**这份工作名单不代表自动晋级或正式晋级结果**；可以加入没有参加展示评审的现有队伍。两阶段的授权、记录和材料快照相互独立，开关或重建一阶段不会改变另一阶段。

**新展示与路演记录阶段尚未实现数值评分和结果计算。** 仅这两个阶段的满分、有效评委人数、汇总公式、晋级名额为空，成绩发布会被阻止。记录数量不代表成绩；原 `#judge`、`#board` 的数字评分和成绩发布不受此限制，两套数据互不迁移、互不汇总。

各阶段评审窗口独立于作品提交、旧评分及观众投票。后台可修改尚未首次开放的关闭轮次名单；首次开放冻结后，无论是否已有评审记录，更换名单或材料都需有理由新建轮次，关闭后重开不会刷新快照。路演首次开放时截取当时的正式材料，不沿用展示阶段的旧快照。框架不包含数值计分、自动晋级或综合排名。

## 后台数据管理

后台支持队伍与评委 CSV 预览、整批导入，以及赛道、参赛状态、退出原因、展位和路演顺序维护。CSV 本体最多 256 KiB、500 行；线上代理仅对导入预览放行 2 MiB JSON，其他请求保持原有较小上限。预览不创建队伍或凭据，15 分钟内仅原管理员会话可确认；目标数据发生变化时，整批拒绝并要求重新预览。路演顺序是组织安排字段，不自动排序或决定晋级。

可按阶段、轮次、队伍、评委、赛道和状态查询记录与缺评，查看冻结材料、修订历史、作废或恢复当前轮记录。作废需要原因，保留反馈和历史，不计入公开正式记录数；评委后续修改也不会自行解除作废。旧轮次只读，升级前的历史只保留已知基线。

队伍、评委、定性记录、人工名单和审计可分别导出 CSV；材料和旧版分数保留独立导出。评委或观众可停用、重发登录码，旧码与旧会话失效；单独重发的评委改用独立码，重启后不会恢复成统一码。明文码只在创建或重发的响应中显示，不进入预览、导出或审计。

作品提交、新展示记录、新路演记录和观众投票分别控制，截止时间按北京时间填写；原专业评分开关另行保留。观众窗口已与专业评分开关分离。尚未实现的是新赛制的数值规则、汇总、晋级、奖项、GOTC 资格和新阶段成绩发布，原专业均分与成绩发布继续可用。

后台的独立展示/路演记录区域会每隔约 3 秒检查变化，只更新所选新阶段的只读记录和数量，保留正在填写的表单，也不覆盖原专业评分设置和统计。轮次或配置变更时提示刷新核对，截止时间到达时更新只读标识；历史筛选、名录、原专业后台统计和审计仍由管理员主动查询或刷新，隐藏标签页暂停自动检查。原专业成绩看板继续按原有 2 秒轮询更新。

集中登录的密码计算不再占用数据库写锁；同时最多执行 4 次密码校验，其他登录在锁外等候。密码强度、登录限流和撤销规则不变。这个并发上限不是在线人数上限，本机合成压测也不能代替线上机器和现场网络验收。

备份和恢复使用 `scripts/backup_event.py`，步骤见 [服务端说明](server/README.md)。恢复只写新目标文件，拒绝覆盖运行中的数据库。
