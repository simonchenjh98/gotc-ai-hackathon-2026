# 现场队伍申请与批准

所有参赛者都可以在 `platform.html#claim` 填写队名、队长与 2–4 名组员的姓名和学校。赛道可选已公布的三条赛道，也可留为待定。空数据库无需导入名单、预建队伍或开放 API 额度即可接受申请。提交只保存待核验申请，不创建人员、队伍或登录账号。

队长保留当前标签页的领取凭据，携全体成员到组织方处出示六位核验码。组织方在后台「现场报名核验」读取申请，核对成员与相关私有身份参考，可修改队名或赛道；确认全体成员已当面核实后批准。系统在同一写事务中分配 1–999 中最小的未使用队号，创建有效队伍、登记或复用人员、绑定成员并发放提交码领取权限。失败全部回滚。队长查询状态后点击领取；重复领取保持同一码。此流程不自动开通 API 网关权限或额度。

私有参考记录仅用于去重，不决定报名资格。同名同校且未归队的记录会复用；已有队伍的同名同校记录会阻止重复归队。同名但不同学校且已归队时，组织方必须当面区分本人，勾选确认并填写说明。旧记录的待核实标记是参考，不要求新参赛者先导入或改写名单。原始记录与备注保留，参考管理和导入入口收在折叠区域内。

申请待审核时，队长可以修改队名、赛道和组员。冲突或保存结果不明时，页面保留草稿，必须读取已保存内容、人工核对并明确确认后才可再次提交。已批准或领码的申请不可改写。旧版无组员的申请须由原领取页面补充；已有组员但没有队名或赛道的旧申请可由组织方补齐。旧请求或更新载荷未包含队伍信息时，不会删除既存队伍信息。

管理员列表提供每份申请的 `reviewContext`，包含申请版本和相关同名参考记录的快照摘要。`POST /api/admin/claims/approve` 提交 `requestId`、`expectedRevision`、`reviewContext`、`teamName`、`track`、`pin`、`inPersonVerified`、`resolvedIdentity`、`note`。批准事务重新验证上下文；相关记录有变化时要求刷新核对，无关人员的变化不会阻塞申请。相同批准载荷可安全重试，包括领码之后。现有 `/api/admin/claims/review` 继续支持旧版名单映射客户端与拒绝操作。

公众只能通过自身 bearer 凭据读取本申请、申报信息和获批队伍，不能查询私有身份、身份匹配结果或管理员上下文。管理员列表不返回 PIN、领取凭据或提交码。现有身份、登录标记、同源写入、请求大小和速率限制继续适用。
