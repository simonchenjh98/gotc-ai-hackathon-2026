# 选手使用流程验收（2026-11-06）

本轮针对 PR #33 的线上申请版本，从首次访问官网检查到正式提交、回执与查分。未改动比赛日程、评分规则或已有身份权限策略。

## 修正的衔接问题

- 申请首次发送期间阻止站内切页和退出，避免服务端已经收到申请但页面丢失领取凭据。未保存的申请输入和队员修改接入离开提醒。
- 从申请页进入选手工作台、切换旧身份时保留独立申请凭据；普通退出仍明确提示并清理共享设备凭据。
- Gitee 仓库批准后刷新，完整切换到简化材料表单，保留作品与展示输入。旧的 README、许可证和来源文本可展开复制到仓库，非适用字段不再拦截提交。
- API 密钥创建成功而后续身份复核暂时失败时，只在原身份内存中保留待验证结果；重试仅重新验证，不再次创建。未通过身份复核不显示密钥，退出或身份变化会清除待验证结果。
- 已绑定仓库的草稿保留服务器已保存的 SHA；无改动保存草稿不再误报材料发生变化。正式预览仍自动读取当前版本。
- 明确组队招募登记为可选步骤，招募管理码不能登录选手工作台；登记成功后提供申请提交码的下一步入口。
- Markdown、下载 PDF 与文本清单同步为线上申请、后台批准、在线领码。PDF 保留六页原有主视觉。

## 验证

- 298 项前端测试、83 项相关后端测试通过；覆盖权限、身份切换、密钥恢复、Gitee 简化字段、线上申请与队伍登记。
- 两项独立代码复核通过；另做 7 个隔离竞态探针，覆盖重试期间身份变化、退出、页面替换和仓库刷新期间继续输入。
- 真实 Chrome 配合临时 SQLite 和合成队伍，走通：线上申请 → 后台批准 → 领码 → 从旧身份切到本队 → API 未开通提示 → 开通后创建密钥及 503 后恢复 → 仓库申请与批准 → 自动 SHA 和封存预览 → 正式回执 → 原样保存草稿 → 历史版本 → 未发布/评分不足/发布后的六维与匿名评语 → 公开榜隐私检查。
- 真实移动浏览器检查了初始表单离开取消、首次请求已入库但响应延迟时的导航保护、刷新恢复申请及待审成员修改的离开取消。
- 首页和独立组队页以 390px、1280px 检查了选手入口、日程切换、提交自查清单、横向溢出及 JavaScript 错误。
- PDF 六页逐页渲染检查通过，文本提取与页面边界检查通过。

## 验证边界

浏览器演练未写入生产数据。Gitee 通过隔离适配器验证站内建仓、版本与封存衔接，没有重复创建真实外部仓库；模型密钥使用临时本地配置，未调用付费模型。强制关闭标签页或首次请求响应完全丢失的跨设备恢复仍不属于本轮导航保护；领取后应保存本队提交码。
