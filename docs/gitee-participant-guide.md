# 代码仓库是可选项
只提交 PPT 和作品压缩包，不需要先申请、绑定或填写代码仓库。

1. **直接提交两项材料**
   用本队提交码登录选手工作台，点击“提交作品”。PPT 和 ZIP 都准备好后，可直接检查、预览并确认；没有仓库不影响交件。

2. **已有仓库，可选择附带版本**
   如果还希望提供代码仓库，在可选项中选择附带仓库版本。已绑定仓库由平台读取正式分支版本；未选择时不会自动读取，也不会要求你等待仓库配置。

3. **需要仓库协作时再申请**
   在“本队代码仓库”按页面提示填写队员开发者用户名、申请和接受邀请。此步骤是协作工具，不是正式交件的前置条件。

## 哪些信息可以留空
- 作品名称与简介。
- 代码仓库与最终 commit。
- README、运行说明、许可证、来源与局限。
- 作品展示链接、HTML 演示和视频。

> **本次必交只有 PPT 和作品压缩包。** 如果可选仓库尚未准备好，取消附带仓库版本，仍可提交两项必交材料。

选手工作台：[登录并提交作品](https://8.141.114.201/gotc/platform.html#team)

尚无提交码：[队伍申请 / 领码](https://8.141.114.201/gotc/platform.html#claim)。按页面提示申请或查询，已有队伍直接使用原提交码登录。

<!-- SECTION: 02 / 整理作品 -->
# 把作品文件统一打包
代码、HTML、图片、样式、脚本及其他相关文件，都可以放进同一个 ZIP。

1. **保留项目结构**
   将作品文件夹打包为 ZIP，保留文件名和各级目录。不要把包内所有文件都改成同一个名字，否则 HTML 和代码可能找不到依赖资源。

2. **包含运行需要的内容**
   检查入口 HTML、源代码和相关资源是否齐全。可附上一份简短说明，写清怎样打开或运行；说明文件是建议项，不影响提交。

3. **检查压缩包**
   在本机打开 ZIP，确认能找到作品文件。作品压缩包不超过 100 MiB；如果使用分享链接，确认无需登录即可下载。

## 可选：写一份作品说明
- **作品用途**：给谁用，解决什么问题。
- **运行方法**：入口在哪里，需要怎样的环境。
- **团队分工**：每位队员负责的内容。
- **来源与限制**：使用了哪些素材，已知有哪些不足。

> 官网提交时，作品名称、简介、README、许可证、来源说明均为选填。请优先保证 PPT 与作品 ZIP 已正式提交。

## 可选：仓库协作
如果使用 Gitee 等代码仓库，可继续 commit、push 保留修改历史。只有主动选择附带仓库版本时，官网才把该版本纳入本次正式材料。

不要将密码、API 密钥或同学个人资料放进公开材料。请另行保留本地项目副本。

<!-- SECTION: 03 / 必交材料 -->
# 只交 PPT 和作品压缩包
登录选手工作台，点击顶部“提交作品”，准备下面两项即可。

| 材料 | 提交方式 |
| --- | --- |
| 1. PPT（必交） | 上传 PPT、PPTX 或 PDF，不超过 50 MiB；也可填写公开 HTTPS 分享链接。 |
| 2. 作品压缩包（必交） | 将代码、HTML 及其他相关文件统一打包 ZIP，不超过 100 MiB；也可填写公开 HTTPS 分享链接。 |
| 其他内容（选填） | 名称、简介、仓库、commit、说明、许可证、来源、作品展示和视频均可留空。 |

## 文件命名
按“队名+作品名称”命名并保留扩展名，例如“星火队+智慧校园.pptx”和“星火队+智慧校园.zip”。ZIP 包内的文件名与目录结构保持不变。

## 可选：作品展示
如果希望评委直接打开演示，可另行上传单个 UTF-8 HTML（不超过 10 MiB），或填写公开 HTTPS 展示链接。HTML 中的图片和脚本应内嵌或使用 HTTPS 资源。

多文件作品可以直接放入必交的 ZIP；不需要为了交件先部署网站。没有 HTML 展示或视频，也可以正式提交。

> 上传文件会返回查看或下载链接，但上传本身还不是正式提交。两项准备好后，继续检查、预览并点击“确认正式提交”。

外部分享链接须无需登录即可访问。建议请队友试着打开 PPT 并下载 ZIP，确认交的是正确文件。

<!-- SECTION: 04 / 提交与确认 -->
# 确认正式提交，保存回执
只交 PPT 和 ZIP 时，不会要求读取仓库版本。

1. **准备两项材料**
   PPT 与作品压缩包上传成功或填写好分享链接。其余内容可以留空；未完成时可先保存草稿。

2. **点击“检查并正式提交”**
   核对预览中的 PPT 和 ZIP，确认本队上传正确。若主动选择附带仓库版本，额外核对仓库和版本编号；不选择则直接预览两项材料。

3. **点击“确认正式提交”**
   这一步才会发送正式材料。请在 13:00 截止前完成确认；不要只停留在上传成功、草稿已保存或材料预览页面。

4. **保存成功回执**
   看到“正式版 v… 已收到”，再复制提交记录或截图留存。没有成功回执时，先查看请求结果，不要直接重复提交。

> **提交成功的标志：正式版 v… 已收到。** 作品名称与简介的单独保存按钮，只保存草稿，不会替代正式提交。

## 回执里核对什么
- 正式版本号与保存时间。
- PPT 和作品压缩包链接。
- 请求编号，以及你主动附带的可选内容。

截止前更换了文件，需要重新检查、预览并确认，才会更新正式版。已有正式材料不会被保存草稿覆盖。

# 打开刚刚交的那一份
回执是交件凭据，正式材料中的链接对应本次保存的文件。

1. **找到本次正式记录**
   在“最近正式材料”查看正式版本号；较早记录可到“正式提交历史”查看。

2. **打开 PPT 和作品压缩包**
   检查 PPT 能下载或查看，ZIP 能下载并包含作品文件。官网直接上传的文件会保留，替换文件会生成新的链接。

3. **检查选填内容**
   如果附带了作品展示、视频或仓库，再检查相应链接。没有填写这些内容，不影响两项材料的正式提交。

## 遇到这些情况怎么办
| 情况 | 处理办法 |
| --- | --- |
| 只看到了材料预览 | 还未正式交件，继续点击“确认正式提交”。 |
| 仓库尚未准备好 | 不附带仓库版本，直接用 PPT 和 ZIP 完成提交。 |
| 断网或结果待确认 | 保留请求编号，查询服务器是否收到，再决定是否重试。 |
| 已过 13:00 截止 | 联系现场组织方，不要以草稿或本地文件作为已提交凭据。 |

> 官网保留直接上传的附件，外部分享链接仍由原平台保存。请保留本地项目与材料副本。回执和截图中不要带上提交码、密码或 API 密钥。

评委查看的是正式材料；保存草稿不会更新正式材料。展示或路演本轮已冻结的材料，也不会因重新提交自动替换。
