# 申请本队 Gitee 仓库
已收到本队仓库链接的队伍，可直接转到第 3 页上传代码。

1. **在线申请队伍，领取提交码**
   官网点击“进入选手入口”，再点“申请队伍 / 领码 ↗”，无需预先进入名单。队长填写本人和 2-4 位组员的姓名、学校，点击“提交领取申请”。管理员批准后，在申请页查询审核状态，点击“领取本队提交码”，领取队伍编号和提交码。用提交码登录“选手工作台”，核对队伍编号和队名；已有提交码可直接登录。

2. **填写队员账号**
   在“本队代码仓库”中选择 Gitee，填写 1-5 位队员的用户名，每行一个。填用户名，不填昵称、邮箱或个人主页网址。

3. **申请仓库，按提示接受邀请**
   点击“申请本队仓库”，等主办方核对用户名。官网会建好本队仓库，并向 Gitee 申请写权限。如果 Gitee 要求加入赛事企业，按邀请提示操作，接受后请主办方核对并刷新仓库状态。

| 页面状态 | 接下来做什么 |
| --- | --- |
| 待核对批准 | 等待主办方审核，不要重复申请。 |
| 正在处理，勿重复操作 | 稍后点击“刷新仓库状态”。 |
| 邀请待接受 | 到 Gitee 查看并接受待处理的邀请，再请主办方核对。 |
| 结果待核对恢复 | 联系技术支持，不要另建仓库或重复申请。 |
| 仓库已绑定 | 打开页面中的仓库链接，开始上传代码。 |

> 只在本队仓库里操作。队员获得本队仓库的协作权限，不需要组织管理权限。用户名填错请联系主办方；申请时不用提供 Gitee 密码或个人访问令牌。

使用原参赛码（原提交码）登录选手工作台，同一登录即可管理本队资料、查看成员、提交作品和查询本队成绩，已有队伍管理码仍只用于原登记资料修改，不可登录工作台。尚无参赛码请在申请页补全队伍成员并等待审核。已审核成员变化请联系组织方；AI API 仍需管理员另行启用。

找不到入口、Gitee 不能选择，或一直无法绑定时，请联系主办方。

# 上传代码，补全项目说明
先把完整项目提交到本队仓库，再准备官网的提交材料。

1. **打开本队仓库，选对正式分支**
   分支可理解为项目里的一个工作区。名字可能是 main 或 master，以官网显示的正式分支为准；核对后再上传。

2. **推荐用 Git 记录每次修改**
   第一次用 Git 的“克隆”把本队仓库复制到电脑。以后开工前先拉取更新（pull）；改完后选中本次修改的文件，写一句说明并提交（commit），再推送（push）。只在电脑上 commit，官网还看不到这次修改。

> 推送后，到 Gitee 刷新正式分支，确认能看到刚才写的提交说明。不熟悉 Git，也可以在 Gitee 用“上传文件”完成提交。保留文件夹结构，不要只放一个 ZIP。

## README.md 至少说明这四件事
在仓库里写好 README.md（作品说明书），把许可证放在 LICENSE 文件里，或在 README 说明允许怎样使用作品。把这些文件和代码一起提交。

- **作品用途**：给谁用，解决什么问题，已经能做什么。
- **运行方法**：需要什么环境，怎样安装、打开和使用。
- **分工与来源**：写明每位队员的工作，并列出用到的 AI、模型、数据、图片和第三方代码的来源。
- **测试与限制**：做过哪些测试，哪些功能或场景仍有问题。

> **不要上传密码、API 密钥、聊天记录或同学的个人资料。** 不要 force push（强制覆盖旧记录），也不要删除正式分支。遇到 gotc-archive- 开头的封存分支，请保留，不要修改、强推或删除。

## 两个词就够了
**仓库**：保存本队项目文件和修改记录的地方。

**版本编号（commit / SHA）**：认出某一次代码提交的一串字母和数字。仓库绑定后，官网会自动读取，不用背，也不用手填。

# 在官网提交三项作品材料
登录选手工作台，点击顶部“提交作品”，先填写作品名称和简介。

| 材料 | 写什么或准备什么 |
| --- | --- |
| 1. PPT | 单独上传 PPT、PPTX 或 PDF（不超过 50 MiB），也可填公开 HTTPS 分享链接。 |
| 2. 代码及其他文件 | 代码 push 到本队仓库。补充文件可打包 ZIP 上传（不超过 100 MiB），保留包内目录结构。 |
| 3. 作品展示 | 上传可直接运行的 HTML（不超过 10 MiB），或填无需登录即可打开的 HTTPS 展示链接。 |

绑定 Gitee 的队伍将 README、许可证、来源与局限写在仓库里，无需重复填写。PPT 建议 5-7 页；视频链接选填，建议约 2 分钟。

## 文件命名和展示要求
1. **统一名称**
   官网上传的文件自动命名为“队名+作品名称”，保留扩展名，例如“星火队+智慧校园.pptx”。外部分享的文件也请按此规范命名。

2. **作品必须直接可看**
   HTML 需为单个可运行文件，图片和脚本内嵌或使用 HTTPS 资源。多文件网站请先部署，再填公开展示链接；只上传 ZIP 或写本地运行步骤不能代替作品展示。

3. **请队友试着打开**
   上传后点击查看，并请未登录你账号的队友测试分享链接。更换文件会生成新链接，旧版提交仍保留原文件。

> 上传文件、push 代码和保存草稿都不等于正式提交。完成三项后，还要检查、预览并“确认正式提交”，看到回执才算完成。官网保存直接上传的文件；外部链接内容仍由分享平台保存。

# 确认正式提交，保存回执
先约好由一位队员完成最后几步，并确认代码已上传到正式分支。

1. **填写材料并完成自查**
   用本队提交码登录，点击“提交作品”，完成 PPT、代码及其他文件、作品展示三栏，勾选材料自查。没填完可以“保存草稿”；草稿还不算正式提交。

2. **点击“检查并正式提交 ↗”**
   官网读取正式分支的最新版本，并创建封存分支。看到“版本已封存”后，核对本队仓库、完整版本编号和材料链接。此时只是预览，还没正式交。

3. **点击“确认正式提交”**
   这次提交会固定使用预览中的版本。队友之后再上传代码，也不会自动换成新版本。预览有效 5 分钟，过期后要重新检查。请在截止前完成确认；截止以服务器接收到有效确认请求的时间为准。

4. **看到成功提示，保存回执**
   看到“正式版 v… 已收到”，再点“复制本次保存记录”，粘贴到自己的文档里；也可截图留存。

> **提交成功的标志：正式版 v… 已收到**

## 回执里，要看这三样
- **正式版本号**：例如 v2，表示官网收到的这一份正式材料。
- **完整版本编号和时间**：确认代码版本正确，保留服务器接收时间和保存时间。
- **请求编号**：用来查询这次操作；它不是登录用的队伍提交码。

> 截止前想改交新代码，要重新“检查并正式提交”并确认。只更新 Gitee 或保存草稿，都不会更换正式版。本轮评审材料若已固定，重交也不会自动替换，请联系主办方。

回执和截图中不要带上提交码、密码或 API 密钥。下一页说明怎样打开这次提交的代码。

# 打开你刚刚交的那一版
回执是交件凭据。官网记录完整版本编号和服务器接收时间，代码保存在 Gitee 的封存分支中。

1. **找到本次正式记录**
   在“最近正式材料”看正式版本号，例如 v2。如果想看更早交的作品，到“正式提交历史”选择对应版本。

2. **打开固定的代码版本**
   在“仓库内项目材料”点“查看这版仓库文件 ↗”，打开的就是提交时的文件。若想核对编号，展开“查看完整哈希”，和回执比一下。

3. **按评委看到的内容自查**
   在这个版本的仓库里看 README、许可证和来源说明；再打开作品展示、PPT 和补充文件，若有视频也一起检查，请队友确认都能看。

## 遇到这些情况怎么办
| 情况 | 处理办法 |
| --- | --- |
| 只看到了“版本已封存” | 此时仍是预览。核对无误后点“确认正式提交”，保存“正式版 v… 已收到”的回执。 |
| 预览后又改了代码 | 想交新代码，先 push 到正式分支，再重新检查、预览、确认。 |
| 断网或显示“结果待确认” | 保留请求编号，点“查询这次请求结果”。先查清是否已收到，再决定是否重交。 |
| 显示过期或已截止 | 预览过期可以重新检查。已过比赛截止时间，请联系主办方。 |

> 收到回执就完成提交，不用等待服务器下载仓库代码。官网保留直接上传的附件；仓库代码保存在 Gitee 封存分支。请保留本地项目和材料，不要删除或强推封存分支。

**评委如何看同一版？** 在评审入口选队伍，在正式材料中点“查看这版仓库文件 ↗”。旧版材料可展开完整哈希，再点“查看此版本 ↗”。专业评分看最新正式版；展示和路演看本轮固定的正式材料。
