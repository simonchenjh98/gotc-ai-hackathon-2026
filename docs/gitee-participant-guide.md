# GOTC 2026｜作品提交小指南

第一次用 Gitee，也可以一步一步来。

**2026-11-05 · 跟着做版**

> 先等老师通知：新功能还没有正式开通。这份手册先用来学习。老师宣布开通后，再按下面的步骤交作品。现在可以先准备账号、作品文件和展示材料。

## 开始前，先认清两个地方

| 去哪里 | 在这里做什么 |
| --- | --- |
| Gitee | 放作品文件的网站，本队队友可以一起修改 |
| 比赛官网 | 像交作业的地方，把准备好的作品正式交给主办方 |

**把文件放进 Gitee 后，还要去比赛官网点“确认正式提交”。这两件事都要做。**

再认两个词就够了：

- **仓库：** 本队在 Gitee 上放作品文件的地方。
- **版本编号（commit / SHA）：** 帮网站认出“你要交哪一次改动”的一串字母和数字。网站会帮你找，不用背，也不用自己敲。

### 准备好这四样

- 一个能登录的 [Gitee 账号](https://gitee.com/)。不会注册，可以请家长或老师帮忙。
- 本队的队伍编号和队名。
- 老师发给本队的“提交码”。它用来登录比赛官网，要保管好。
- 一位负责最后提交的队员。最后几步由这位队员来点。

Gitee 用自己的账号和密码登录。比赛官网用本队的提交码登录，各用各的。

**比赛官网：[https://etownyouthai.com/](https://etownyouthai.com/)**

## 第 1 步：申请本队的网上文件夹

老师如果已经发给你本队的仓库网址，可以直接看第 2 步。不要去公共模板或别的队伍的仓库里改文件。

1. 打开比赛官网。
2. 找到“申请 Gitee 仓库 / 提交作品 ↗”，点进去。
3. 用老师发的本队提交码登录。
4. 看一眼队伍编号和队名，确认是自己队。
5. 找到“本队代码仓库”，选择 Gitee。
6. 填本队队员的 Gitee 用户名，一行一个，最多 5 人。填用户名，不填昵称、邮箱或网址；找不到用户名就请老师帮你核对。
7. 点“申请本队仓库”，等老师检查。用户名填错了，要马上告诉老师，别再申请一遍。
8. 如果 Gitee 发来加入邀请，按提示接受，再告诉老师。回到比赛官网点“刷新仓库状态”。

> 看到“仓库已绑定”，就说明本队的网上文件夹准备好了。点里面的仓库网址，就能去放作品文件。

### 页面上这样写，就这样做

| 你看到的文字 | 接下来做什么 |
| --- | --- |
| 待核对批准 | 等老师检查，不要重复申请 |
| 正在处理，勿重复操作 | 稍后点“刷新仓库状态” |
| 邀请待接受 | 到 Gitee 看看邀请，接受后请老师检查 |
| 结果待核对恢复 | 找老师帮忙，不要另建一个仓库 |
| 仓库已绑定 | 打开仓库，开始第 2 步 |

如果找不到按钮，或 Gitee 不能选，先问老师是不是还没开通。

你不需要把 Gitee 密码或私人令牌交给老师，也不要把它们写进作品里。

## 第 2 步：把作品文件放进 Gitee

“代码”就是让作品运行的那些文件。先把文件传到本队的 Gitee 仓库，别人才能看到你们做了什么。

### 用浏览器上传

1. 打开本队仓库的网址，先看清仓库名字。
2. 找到写着 `main` 或 `master` 的小菜单。这叫“分支”，可以理解为同一个项目里的不同工作区。**官网写哪个名字，就选哪个名字。** 不确定就问老师，不要随便换。
3. 找到“上传文件”，选择本队要上传的项目文件。
4. 写一句话说明这次改了什么，比如“修好了开始按钮”。
5. 按页面提示点“提交”。等它完成，再回到仓库刷新。
6. 看看新文件或新改动有没有出现。**能在仓库里看到，才说明传上去了。**

代码如果有很多文件夹，请老师或会用 Git 的队友帮忙保留文件夹结构。不要把文件全部混在一起，也不要只传一个 ZIP 压缩包就当作完成。

### 再写一份作品说明书

仓库里叫 `README.md` 的文件，就是项目说明书。它至少要回答：

- 这个作品能做什么？给谁用？
- 别人拿到作品后，怎样打开、怎样运行？
- 谁做了哪些事？用了哪些 AI、图片、数据或别人的代码？
- 哪些功能还没做好？做过哪些测试？

要修改它，可以打开文件，点“编辑”。如果进入 Web IDE，改完后点“创建提交”，在“更改”旁点加号暂存，再写说明并提交。不懂时请老师帮忙。

> 不要上传密码、API 密钥、聊天记录或同学的个人资料。API 密钥是调用 AI 等服务时用的秘密凭据，要放在自己的私有设置里。

**不要使用 force push（强制覆盖旧记录），也不要删除正式分支或旧版本。** 如果这样弄丢了已交的版本，本队要负责。看到 `--force` 或不认识的删除选项，先停下来问老师。

## 第 3 步：把要交的材料准备好

先在电脑里准备，再去官网填写，会更容易。

| 要准备什么 | 写什么或放什么 |
| --- | --- |
| 作品名字和介绍 | 给谁用？解决什么问题？最主要能做什么？ |
| 作品说明书 README | 让别人看懂作品，并知道怎样运行；准备它的网址 |
| 使用和来源说明 | 许可证说明要写清别人能怎样使用你们的作品；不懂请老师帮忙确认。借了谁的图片、代码、模型或数据，也要写清 |
| 作品演示 | 有演示网址就准备网址；没有，就写清现场怎样打开和操作。两种至少准备一种 |
| 展示材料 | 5-7 页 PPT 或其他展示材料，准备可以打开的网址 |
| 演示视频 | 约 2 分钟，展示一次主要操作过程，准备视频网址 |
| 还没做好的地方 | 如实写，不用把没完成的功能说成已经完成 |

页数、视频时长等要求，最后以老师和主办方通知为准。

### 怎样交 PPT 和视频？

1. 先把 PPT 和视频放到主办方允许的分享平台。
2. 打开分享设置，取得可以查看的网址。官网要求完整的 HTTPS 链接，也就是以 `https://` 开头的地址。
3. 请一位没有登录你账号的同学试着打开。**对方不用申请权限就能看到，才适合交。**

不要只填电脑上的文件名，比如“我的作品.pptx”。老师打不开你电脑里的这个文件，要填能在网上打开的链接。

> 比赛官网是收材料网址的地方，不是上传 PPT、视频文件的地方。作品文件放在 Gitee，PPT 和视频按老师指定的办法分享。

官网显示“仓库已绑定”后，仓库地址和作品版本编号会由网站帮你找。你不用手填这两项，只要检查是不是本队的仓库。

## 第 4 步：到官网正式交作品

> 这一步开始前，先让队友暂停更新 Gitee，约好由一位队员完成最后提交。

1. 打开比赛官网的作品提交页，用本队提交码登录。
2. 确认队伍编号和队名是本队，再把第 3 步准备的材料填进表格。
3. 没填完，可以先点“保存草稿”。**草稿只是先存着，还没有正式交。**
4. 材料都准备好后，勾选材料自查。意思是“我已检查这些材料”。
5. 点“检查并正式提交 ↗”。有红色提示，就按提示补好。网站会先把要交的内容给你看一遍，这叫“预览”，还没有正式交。
6. 在预览里看看：仓库是本队的吗？材料网址对吗？作品是不是最后想交的那一版？网站显示的版本编号，不用自己重打一遍。
7. 确认没有选错，再点“确认正式提交”。
8. **看到“正式版 v… 已收到”，才算正式交成功。** 点“复制本次保存记录”，把记录保存到自己的文档里，也可以给“已收到”的页面截图。

这份“已收到”的记录，叫作**回执**。它告诉你：网站收到了哪一版作品。

### 最后看清这两件事

- **版本预览只管 5 分钟。** 如果过期了，或队友在预览后又更新了作品，就再点一次“检查并正式提交”，重新检查后再确认。已填的文字会保留。
- **作品后来改了，不会自动重交。** 截止前想交新版本，要再次检查、预览、确认。只改 Gitee 或只保存草稿都不算重交。

网站保存的记录里会有“请求编号”，它用来查这次操作的结果。它和本队登录用的提交码不是同一回事。

保存回执时，不要把提交码、密码或 API 密钥一起截图。回执也不是作品备份，电脑里还要保留一份作品。

如果页面说本轮评审已经固定了材料，后来重交可能不会换掉本轮评委看到的那一份。先问老师再处理。

## 遇到问题，先看这里

| 你遇到什么 | 可以怎么做 |
| --- | --- |
| 看不到提交按钮，或提示没开通 | 找老师确认开放时间，不要一直刷新 |
| 仓库打不开，或不能传文件 | 核对登录的账号和仓库名字，把报错告诉老师 |
| 预览过期，或提示版本变了 | 文字不用删，再点“检查并正式提交”，重新核对 |
| 提示次数太多，或仓库服务繁忙 | 先等一分钟再试。出现繁忙提示不代表交成功 |
| 网络断了，显示“结果待确认” | 先保存输入和请求编号。如果有“查询这次请求结果”，先点它。暂时没查到就再等一会，不要连续重交 |
| 提示材料版本冲突 | 先把自己的文字复制保存，再请老师帮你对照最新材料，不要随便点放弃 |
| 提交时间已经结束 | 联系老师处理，反复刷新或改电脑时间都没用 |

提交前逐项确认：

- [ ] 作品文件已经放进本队的 Gitee 仓库。
- [ ] 作品说明、PPT、视频等材料的网址都能打开。
- [ ] 材料里没有密码、密钥或同学的个人资料。
- [ ] 已看到“正式版 v… 已收到”，并保存了提交记录。
- [ ] 自己电脑里还留着一份作品和演示材料。

**记住：先把文件放进 Gitee，再去官网正式交，最后保存“已收到”的记录。**
