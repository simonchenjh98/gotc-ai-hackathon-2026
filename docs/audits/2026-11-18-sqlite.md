# Event database migration and measurements

The synthetic event created by commit `d0b6042` contains 65 application tables and 36 triggers. The production audit reports 67 live tables. The new baseline checks the historical application tables, their required columns, and the rollback and integrity triggers, accepts additional objects, and preserves them. No production schema inventory or data was read for this rehearsal. A fresh candidate has 66 application tables after adding named administrator authentication. Gateway content resides in a separate private database.

Each service opens the event store before accepting requests. An operating-system lock in the private data directory serializes setup across both processes, including initial keys, legacy snapshots and numbered upgrades. Unnumbered installations first follow their original domain upgrade order. SQLite records the completed migration in `PRAGMA user_version`. Version 1 verifies the historical baseline and foreign keys. Version 2 adds named administrators. Version 3 migrates gateway content and applies the opt-in policy. Later startup checks reject unknown versions. A transaction failure leaves the last completed version intact. Reopening a current store reloads runtime configuration and reconciles history written by a compatible older binary.

The platform alone schedules cleanup every five minutes. Each transaction removes at most 512 expired records per table from sessions, finals access tokens and import previews. A passive WAL checkpoint then copies available pages without waiting for long readers to exit. SQLite's normal automatic checkpoint remains enabled. A long reader can prevent a complete checkpoint; investigate it if the WAL keeps growing. Each service process has up to eight connections. Nested leases on a worker thread use savepoints and share its transaction. An exception rolls back that scope. Active database work finishes before its connection is returned or closed.

## Synthetic rollback

Before an operational upgrade, stop writes and preserve the complete private data directory together with launcher credentials. Rehearse restoration to a separate directory. The tests restore an unnumbered synthetic snapshot, check account records and foreign keys, and verify the original version separately from the upgraded store. A previous binary cannot enforce new TOTP and content-retention policies. After activating those features, use a compatible forward fix. Replacing a live database with an old snapshot discards subsequent activity. The deployment does not automatically vacuum the database or remove old backups.

### Archived-source rehearsal

The actual archived `d0b6042` process created a synthetic team (number 77) and two additional operator tables. It closed with version 0 and 67 application tables. The candidate upgraded a separate copy to version 3 with 68 tables. The second startup retained the same count. Both reads verified the team, preserved extension row and an empty foreign-key check. The archived binary then opened a separately restored pre-upgrade snapshot, at version 0 with 67 tables, and read the same team and extension row. No production data or schema was contacted.

Run from the candidate checkout using its installed interpreter. Each invocation starts a fresh Python process and imports the service from the selected checkout.

```sh
REHEARSAL=$(mktemp -d)
GOTC_PYTHON="$PWD/.runtime/venv/bin/python"
mkdir "$REHEARSAL/base"
git archive d0b6042 | tar -x -C "$REHEARSAL/base"
cat > "$REHEARSAL/check.py" <<'PYCODE'
import sys
from pathlib import Path
mode, source, data = sys.argv[1:]
sys.path.insert(0, str(Path(source).resolve()))
from backend.gotc.service import EventService
event = EventService(data_dir=data, origin="http://127.0.0.1")
with event.db() as db:
    if mode == "seed":
        db.execute("INSERT INTO teams VALUES ('fixture',77,'Synthetic','','',100)")
        db.execute("CREATE TABLE operator_mock_a(note TEXT)")
        db.execute("CREATE TABLE operator_mock_b(note TEXT)")
        db.execute("INSERT INTO operator_mock_b VALUES ('preserve')")
    assert db.execute("SELECT number FROM teams WHERE id='fixture'").fetchone()[0] == 77
    assert db.execute("SELECT note FROM operator_mock_b").fetchone()[0] == "preserve"
    assert db.execute("PRAGMA foreign_key_check").fetchall() == []
    version = db.execute("PRAGMA user_version").fetchone()[0]
    count = db.execute("SELECT count(*) FROM sqlite_schema WHERE type='table' AND name NOT LIKE 'sqlite_%'").fetchone()[0]
    assert (version, count) == ((3, 68) if mode == "candidate" else (0, 67))
    print(mode, version, count)
if hasattr(event, "connections"):
    event.connections.close()
PYCODE
"$GOTC_PYTHON" -B "$REHEARSAL/check.py" seed "$REHEARSAL/base" "$REHEARSAL/original"
cp -R "$REHEARSAL/original" "$REHEARSAL/upgraded"
"$GOTC_PYTHON" -B "$REHEARSAL/check.py" candidate "$PWD" "$REHEARSAL/upgraded"
"$GOTC_PYTHON" -B "$REHEARSAL/check.py" candidate "$PWD" "$REHEARSAL/upgraded"
cp -R "$REHEARSAL/original" "$REHEARSAL/restored"
"$GOTC_PYTHON" -B "$REHEARSAL/check.py" restored "$REHEARSAL/base" "$REHEARSAL/restored"
```

## Connection and durability measurements

One worker issued 600 measured transactions after 50 warmups against 16,384 synthetic 1 KiB records in a local temporary WAL database. Every fourth transaction updated one row. Each read sampled 24 indexed rows. Both runs used the same Apple Silicon host, Python 3.12.12, SQLite 3.50.4 and deterministic input. These are SQL timings on a warmed host, excluding HTTP and application work.

| Profile | Read p50 / p95, µs | Write p50 / p95, µs |
| --- | ---: | ---: |
| Previous release, new connection per transaction | 309.6 / 424.3 | 373.8 / 557.6 |
| Candidate with original FULL, 2,000 KiB cache, mmap disabled | 39.4 / 49.6 | 44.4 / 62.2 |
| Candidate with NORMAL | 39.0 / 44.5 | 16.1 / 19.8 |
| Candidate with 4,096 KiB cache | 39.6 / 46.8 | 43.8 / 52.5 |
| Candidate with 32 MiB mmap | 31.3 / 37.3 | 44.1 / 52.0 |

The default stays FULL. NORMAL can lose recently acknowledged commits after a host power failure. The larger cache and mmap results were from one synthetic process on a developer machine. Raising per-connection memory budgets needs a separate measurement with both services and other workloads on the small target host. [Raw measurements](2026-11-18-sqlite-benchmark.json)
