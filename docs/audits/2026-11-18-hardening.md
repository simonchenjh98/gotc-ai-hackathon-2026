# Platform hardening implementation and acceptance

This report tracks the six phases of the 18 November rebuild brief against `d0b6042`. All event records, organizer accounts, upstreams, certificates and keys used for validation were synthetic. The working tree contains the changes. Production was not accessed.

## What changed

| Brief phase | Implementation | Evidence |
| --- | --- | --- |
| 1. Authentication and privacy | Protected writes check the actor before acquiring the SQLite writer reservation and recheck under the transaction. Login throttling is scoped to the peer and account/selector, with a separate bounded password-hash budget. The team sign-in path rejects organizer credentials. Named organizers enroll an individual credential and TOTP before the legacy login is retired. | [Account migration and rollback](../organizer-accounts.md) · [Write-authorization tests](../../tests/backend/test_write_authentication.py) |
| 2. Platform HTTP | Starlette route declarations bind request policy and domain operations. Uvicorn owns HTTP parsing, framing, response transport and connection lifecycle. Native responses serve streams, material downloads and conditional reads. In production only the configured Unix-socket path is trusted for proxy identity. | [Declared routes](../../backend/gotc/http/routes.py) · [Transport tests](../../tests/backend/test_http_transport.py) |
| 3. Gateway | The independent ASGI gateway uses async HTTPX for model, media and task requests. Starlette and websockets handle speech connections. Team and global admission limits bound running and waiting work. Metadata stays in the event store. Opt-in request/response content has its own private database, retention worker and backup policy. | [Network architecture](../architecture.md) · [Content retention tests](../../tests/backend/test_content_retention.py) |
| 4. Database | Three numbered migrations baseline pre-existing stores, introduce named administrators and separate retained content. Startup serializes upgrades across processes. Connections are reused, with foreign keys and WAL enabled. The platform schedules bounded deletion of expired state and passive checkpoints. FULL synchronization remains the default. | [Migration, rollback and SQLite benchmarks](2026-11-18-sqlite.md) |
| 5. Frontend and origin | The build generates content-addressed scripts and styles with integrity metadata. The signed-out portal defers the route integrity map. Nginx handles the static site, cache policy, compression and HTTP/2. A configured public HTTPS origin drives production URLs. Untrusted rendering paths are documented and tested. | [Rendering audit](frontend-rendering.md) · [Nginx configuration contract](../../ops/deploy/nginx.md) |
| 6. Operations | Separate service units have independent resource limits. Local readiness, liveness and metrics distinguish platform and gateway health. Logs use generated request IDs and route categories. CI includes dependency auditing, static checks, secret scanning, browser tests and offline artifact rehearsal. | [Deployment handbook](../../ops/deploy/README.md) · [Security jobs](../../.github/workflows/security.yml) |

GitHub and Gitee credentials travel in the Authorization header. Gitee’s published API schema lists an optional query parameter, and OSChina’s own client for the same API demonstrates bearer-header authentication. The regression checks the actual URL, headers, redirects and logs against a local provider. Systemd credential files and private development files use one credential loader. Existing event peppers and roadshow keys must match their provisioned values. [Gitee schema](https://gitee.com/api/v5/doc_json) · [OSChina REST client](https://github.com/oschina/mcp-gitee/blob/150246f3a53a5ba1c6afcd05704378722e486339/utils/gitee_client.go#L180) · [Credential tests](../../tests/backend/test_credentials.py)

## Local performance and boundaries

| Measurement | Archived `d0b6042` | Candidate | Interpretation |
| --- | ---: | ---: | --- |
| Team login p95, idle → both team gateway slots occupied | 22.581 → 23.829 ms | 21.057 → 21.679 ms | Candidate occupied/idle was 1.030×, within 2× |
| Draft submission p95, same conditions | 3.031 → 3.061 ms | 1.407 → 1.585 ms | Candidate occupied/idle was 1.127×, within 2× |
| Signed-out login first visible, median | 505.3 ms | 506.5 ms | Five cold Chromium runs per build, a 1.2 ms difference |
| Pooled SQLite read p95 | 424.3 µs | 49.6 µs | Both runs kept FULL synchronization |
| Committed SQLite write p95 | 557.6 µs | 62.2 µs | Each run used a fresh event store |

Twenty normalized HTTP contracts matched the reference. Ten end-to-end browser journeys passed, including named/TOTP enrollment-mode login, legacy login during migration, and delegated access. The occupied-case test used two legitimate model calls on a delayed synthetic provider, 24 paired login and draft samples per condition, and separate local service processes. [Acceptance method, p50/p95 and raw results](2026-11-18-asgi-acceptance.md)

The SDK microbenchmark starts a fresh gateway, team account and loopback provider. It completes five warm-ups per endpoint, then times 25 whole HTTP responses per endpoint. The comparison alternated the two versions across three runs. Reproduce it with `python tests/performance/gateway.py --source /path/to/d0b6042` and `python tests/performance/gateway.py` using the same interpreter. Use the runtime virtual environment for the candidate. [Raw SDK samples](2026-11-18-asgi-gateway-timing.json)

Across the three runs, median model listing fell from 0.982 to 0.770 ms. Complete chat rose from 2.942 to 3.696 ms and complete streaming from 2.973 to 3.869 ms. These loopback measurements exclude external inference time. They show that stronger isolation and faster event writes coexist with extra overhead on small model calls.

Four legitimate calls across two teams also exercised 33,554,432-byte requests and 50,000,000-byte replies. The gateway serializes bulk materialization, spools large request data to private temporary files and applies response backpressure. Two waves returned matching bytes and recorded usage. Maximum process RSS on the ARM64 macOS fixture was **263.7 MiB with content capture off and 281.9 MiB with it on**. That exceeds the initial 256 MiB gateway ceiling. The configured limits are now 256 MiB for the platform and 384 MiB for the gateway. Together the units can be capped at 640 MiB. Systemd allocates memory on demand. On the measured request shape the gateway has 102.1 MiB of margin. Linux cgroups also account for resources such as file cache. Measure a production-like Linux cgroup with representative payload shapes and the host's other services before rollout. [Maximum-payload commands and raw measurements](2026-11-18-gateway-memory.json)

The access controls intentionally change organizer login and proxy identity. Uvicorn’s h11 backend normalizes identical duplicate Content-Length values before ASGI. The production Nginx edge rejects duplicate lengths and the application rejects ambiguous framing visible to it. Uvicorn rejects duplicate WebSocket Origin headers with HTTP 400 before application CORS runs. A client that abandons an upload can receive EOF. Cleanup tests check that partial files are removed and no receipt is recorded. A database down-migration after enabling TOTP requires the separately tested recovery procedure.

## Rollout boundary

The release builder packages the reviewed wheels for offline installation. The trusted host helper verifies a detached CI signature binding the archive digest to its source commit. The upload account and non-login runtime build account have separate identities. Locally tested cases include the wrong signer, altered archive, mismatched commit, pre-activation failure and restoring the previous units. The production CI signing key and host trust anchor require independent operator provisioning.

`make check` and `make test` passed on Python 3.12 with local Nginx available. The final per-suite runs covered **594 frontend tests, 830 backend tests, 26 operations tests and ten Chromium journeys**. The integrated test command included 593 frontend tests; the standalone frontend rerun included the last dashboard case. A separate two-process test verified that the organizer sees two running calls and one queued call, gets an unavailable state while the gateway socket is absent, and recovers on reconnection. Further local checks included the CI Ruff rule set, strict typing of the edge and asset configuration, a locked dependency audit and redacted source secret scanning.

The archived baseline had 65 application tables on a fresh synthetic event. A second rehearsal added two extra tables, upgraded it twice, then reopened a separately restored original with the archived code. It preserved the team, both extra tables and foreign-key consistency. [Database rehearsal and raw timings](2026-11-18-sqlite.md)

The target is a host shared with other services. Local measurements do not establish capacity on that host. The organizer must supply the approved domain and certificate, service identities, proxy-socket permissions and release trust configuration, and rehearse the Linux systemd/Git restrictions before rollout. Historical backups can retain old content and need an organizer-approved retention and restore procedure. Disk cleanup, live data deletion, host SSH policy, and changes to unrelated Nginx locations were outside this implementation. [Release and rollback instructions](../../ops/deploy/README.md)
