# 决赛邀请码入口

按组织方的新要求，决赛入口改为先验证统一邀请码，再选择评委席位。邀请码沿用服务器私有管理码配置，真实值不进入源码、测试或公开说明。

- POST `/api/finals/access` 验证邀请码并签发仅用于决赛的有限期随机凭据，数据库只保存哈希及校验标签；不创建普通管理员会话。
- 名单、个人评分读取、评分写入和提名写入均须携带凭据，在后端验证有效期与当前私有码；写入在数据库锁内重新验证。
- 前端只在当前标签页的会话存储保存短期凭据，不保存邀请码；刷新后可继续使用，过期或撤销后返回验证。席位仍明确由本人选择，各自记录独立。
- 公开成绩看板保持公开，组织方后台使用原有管理员验证。计分、奖项、窗口和名单规则继续使用现行实现。
- 覆盖未验证绕过、错误码、过期、码轮换、权限隔离及迟到响应；完整 CI 通过后部署，并在线验证拒绝未授权请求和正确邀请码可读取名单。
