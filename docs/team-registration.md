# 组队登记

首页 `#teams` 与云端 `teams.html` 共用服务器名单。队长可先登记 1–5 个真实姓名，目标人数为 3–5 人，未满员标记待补充。登记成功后请保存独立的组队管理码，之后凭码修改；管理码不是提交码，不授予作品、评分或模型访问权限。需要提交码时，队长在 `platform.html#claim` 填写含队长共 3–5 人的队伍申请，组织方后台审核时主动选择本队已有登记，批准后复用同一队号和队伍 ID，不重复创建队伍。审核显示登记队长、学校与成员，批准会按审核通过的申报更新这些字段；原项目、联系方式、来源、原始记录和管理码保留。已批准成员不可通过管理码改写。详见 [队伍申请审核](team-claims.md)。

公开列表只返回队名、队长、学校、姓名、人数、项目和补充状态。电话、原表、管理码哈希保存在私有数据库；代码和真实名单不得放进 Git。组织方在平台后台的“组队登记与管理码”查看联系方式、核对项目和重发管理码。遗失的明文码不能读取，只能重发；重发不会改变作品提交码。

`GET /api/registration` 返回公开名单；`POST /api/registration/create|open|save` 使用随机 32 字节管理码。创建前由浏览器生成并暂存在当前标签页，同一码重试不会重复建队。保存带 `expectedRevision`；本模块和其他队伍编辑器改名、改项目后都会使旧版本失效。已批准成员与已正式提交的项目名不能从登记页改写。

`GET /api/admin/registration` 与 `POST /api/admin/registration/rotate|import` 要求管理员及 `X-GOTC-Login`。导入参数 `rows` 每项为 `{sourceKey,team,raw}`；只新增，不覆盖既有来源编号。同批有非法条目时整批回滚。正常 HTTP 请求上限仍为 16 KiB，大名单按小批发送。每次导入仅在响应返回新队伍的管理码，应立即保存至私有文件。

用户给定名单在部署后通过管理员接口私有导入，先备份正式数据库。空行忽略；重复队长与“欢迎加入”等占位不计人数；原始字段仍完整保留。原表缺队名、人数缺失或与姓名数不符只作标记，不猜测人员或更改原始人数。原有私有报名名单不覆盖；已知姓名保留其原学校，未提供学校的新队员标为待核对。

主页跨域请求只对 `etownyouthai.com`、`www.etownyouthai.com` 和项目 GitHub Pages 来源的公共登记路径开放，不携带 Cookie。管理员及其余 API 的 Origin 与页面登录身份校验保持不变。登记限制为每分钟每 IP 20 次操作、最多 200 队；组织方通过后台审核队伍申请及归属；普通批准不要求私信、核验码或到场。

回退可部署前一版本，新增表不会影响旧版本；不要删除数据库。导入的队伍属于原 `teams` 表，回退前应先核对是否已有成员审批、作品或评分，不能直接批量删除。
