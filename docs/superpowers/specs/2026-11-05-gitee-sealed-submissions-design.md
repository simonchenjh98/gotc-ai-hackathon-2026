# Gitee 封存引用、快速确认与异步源码备份

## 用户已选定的设计与范围

用户要求先用专门测试仓库核对当前套餐；可用时实现“Gitee 上锁定版本、官网只处理小请求、后台再备份”。用户没有普通 Gitee 账号，明确接受普通选手按仓库 push 权限受平台规则约束的假设；不能将此假设写成普通账号实测通过。公开仍须主办方逐队、逐正式版本确认；本次不自动公开任何新归档文件。

本次交付一个纵向功能：Gitee 预检查建立受保护的确切 SHA 引用 → 展示锁定版本 → 截止前确认仅写本地数据库 → 新正式版与封存证据一起持久化 → 后台限速抓取同一 SHA，私有保存源码 ZIP、可独立恢复的 Git bundle 与清单 → 队伍/组织方查询备份状态和下载。评委仍可从现有正式材料打开固定 commit 页面。PPT/视频仍为外链，本次不宣称已备份这些文件；不新增公网作品目录、自动发布或 OSS 付费资源。

## 真实套餐测试与信任边界

2026-11-05 在 gotc-ai-hackathon/gotc-acceptance-20261105-896659（仓库 ID 51277411）测试：

- API 按完整 SHA 创建分支成功，起点可以是较早提交而非分支当前 head。
- 先创建的保护通配符会覆盖之后新建的分支；仅管理员推送/合并规则可配置。
- 对分支增加精确的 pushers=none、mergers=none 规则后，管理员的 Git 正常推进、真正非快进强推、删除均被服务端拒绝。非保护分支正常推进成功，排除认证失败假阳性。
- 管理员的 contents API 仍可无提示地追加新提交；不能称为所有管理员入口不可修改。原 SHA 仍可读取。API DELETE branches 无对应官方端点，405 不能计为保护测试通过。
- 普通账号 Git/API 尚未执行。本功能依赖 Gitee 对开发者与管理接口的角色隔离。组织方及服务器令牌属于可信管理方；选手只获精确 push 权限，仍按既有逻辑拒绝 admin 开发者。

正式提交永远取确认的原 SHA，不跟随封存分支后来可能由管理员 API 产生的新 head。所有外部仓库身份继续核对数字 ID；任何同名不同身份或不同 SHA 的引用禁止覆盖、强推或无声替换。master 和已有正式 v1 未在套餐探针中修改。

## 封存与确认合同

Gitee 专属显式开关 GOTC_REPO_GITEE_SEAL_ENABLED，只有精确 1 启用。GitHub 和未启用的 Gitee 保留现有流程。每队、每仓库身份建立持久随机封存命名空间，先用管理员-only 通配符保护创建入口，再按完整 SHA 创建引用并加精确 none/none 规则。读回引用 SHA、protected 和规则响应均匹配后才可生成有效预览。复用同一 SHA 不重复建分支；结果不确定时按原操作标识恢复，绝不新建替代版本。所有上游工作在 SQLite 写锁外，沿用四个 provider 许可和预览限额。

五分钟预览仍绑定队伍、当前登录和绑定修订；关联独立封存记录。最终确认使用这些本地证据，不再访问 Gitee。确认的是预览版；预览后新 push 需重新检查才会提交新版本。身份撤销、绑定变化、预览过期及关闭窗口仍拒绝。

HTTP 层在完整合法 JSON 到达服务端后记录 trusted receivedAt；客户端不能提供/覆盖。封存确认按 receivedAt 与截止比较，数据库排队越过截止不应使按时有效请求变迟交；原有保存时间仍记录真实入库时间，回执另加 receivedAt。手工关闭窗口或身份撤销仍按当前权限生效。旧流程、GitHub 行为与原始成功回执重放保持兼容。

新正式历史、封存关联、接收时间和原始请求回执在同一事务中写入；成功重放不再产生远端操作、封存引用、历史版或备份任务。旧不可变历史/回执不回写。

## 异步私有源码备份

GOTC_REPO_BACKUP_ENABLED 只有精确 1 启动主进程中的一个后台 worker，测试服务构造不会自动起线程。任务跟正式版一起排队，SQLite 只在认领和结果提交时持写锁。先下载到私有临时目录、校验确切 SHA 和完整性，再原子发布私有包与清单。失败保留同一 SHA 重试，最后失败也不改动原正式记录或上一版备份。重启可恢复未完成任务。

默认限制：单 worker；轮询 5 秒；最多 3 次尝试，前两次失败分别等待 60、300 秒；Git 操作墙钟上限 180 秒；单任务磁盘上限 268435456 字节；归档存储总上限 2147483648 字节；源码解压内容上限 134217728 字节；最多 20000 个文件。硬限额须实际执行，不能只在完成后检查。来源只允许绑定的官方 Gitee HTTPS 仓库；不跟随重定向、不递归抓子模块、不运行钩子、过滤器、构建或选手代码。令牌只通过私有环境/askpass 传给 Git，不进入 argv、URL、包、清单和错误日志。

备份按原 SHA 建自包含 bundle，生成包含本 commit 跟踪文件的 ZIP；不能因 export-ignore 丢掉已跟踪文件。文件名和符号链接不在服务器解包或执行。识别 LFS 指针和子模块，清单明确缺失内容并标 partial，不能称为完整可运行项目。PPT/视频没有被此 worker 抓取。

状态 queued/running/ready/partial/failed 独立于 submitted。默认私有存储，不在发布包或静态路径。受限下载仅组织方与本队；评委仍通过已有材料固定 commit 链接查看，不扩大现有历史读取权限。公网匿名下载拒绝。本次不自动公开任何备份。

## 展示和可验证性

预览明确显示“版本已封存，确认将保存此版本”，旧模式仍提示重新核对 head。回执/历史显示 receivedAt、封存引用、固定 commit 浏览链接与源码备份状态。始终区分 Gitee 引用封存和独立字节备份。没有备份任务的旧版本明确标为未归档，不能套用新版本状态。提交失败、备份失败均保留输入；已成功请求按编号查询原回执。

验证包含：真实套餐测试报告；故障/丢失响应恢复；先保护入口再建引用；精确 none 响应；无写锁期间远端请求；跨队/会话/修订隔离；确认不调用上游；后续 main 变化不替换选定 SHA；可信接收时间与截止边界；原始回执幂等；备份正确 SHA、Git bundle 恢复、ZIP 含 export-ignore 文件、LFS/子模块 partial、额度/超时/失败恢复与私有下载授权；旧有服务端、Node、发布包与回滚回归。上线前独立审查；测试配置和明文凭据不进 Git/PR。
