# 组织仓库申请与固定版本正式提交

用户已选择：GitHub/Gitee 组织管理每个项目的独立仓库和本队写权限，官网承担队伍申请、绑定与正式提交；自动取得完整 SHA，选手不用填写仓库/commit。官网正式域名为 https://etownyouthai.com/ 。

本次是一个完整纵向功能：本队身份申请 → 主办方核对账号并批准 → 服务端创建本队仓库并邀请开发者 → 本队查看绑定仓库 → 获取正式分支当前 SHA 并预览 → 确认后原子保存现有回执/历史。未配置组织凭据时明确显示尚未启用；不伪装远端成功，不自动回退到手填版本。

组织凭据仅从服务器私有配置/环境读取，不进入前端或报告。GitHub/Gitee 分开配置允许的组织、分支和令牌；只调用固定官方 API 主机，不接受选手输入任意远端 URL。Gitee 当前企业免费额度 5 人且与普通组织接口兼容性未验收，因此该渠道必须显式启用，不能宣称已经联通。主办方核对申请中的用户名归属后才批准，选手不获企业管理权限。

每队至多一个正式仓库；仓库名由服务器以队伍编号和内部 ID 生成，不能撞名后认领既有仓库。远程请求不长时间占数据库写锁。申请及建仓状态留审计；网络结果不确定时保持可核对状态，不盲目重复创建或授权。新仓库仅含非敏感初始化文档。开发者仅获得本仓库写权限，主办方保留管理权。默认关闭 force push，若套餐不支持则明确保留未验证状态，规则不能代替归档。

预览由服务器读取绑定仓库的固定分支，保存短期、绑定本队和当前登录的预览记录，包含完整 SHA 和仓库绑定修订。确认前重新核对分支 head，改变则拒绝并要求重新预览，不能静默换成新 SHA；同一请求回执重放需沿用原有成功语义。正式记录中的 codeUrl/codeVersion 以服务端绑定及预览值为准，拒绝绕过预览或夹带别队仓库。草稿保存兼容旧字段；未绑定旧队伍仍保留原有流程，已绑定队伍隐藏手填项。

提交规则明确禁止 force push/删除正式分支/移除正式提交；选手承担违反规则造成的不可用后果。主办方仍应独立归档完整 SHA 对应源码，界面必须准确区分“记录版本”与“代码已归档”。本次不以下载代码包冒充含子模块/LFS的完整存证。任何未实现的归档状态必须明示。

验证包括申请权限、队伍隔离、管理员批准、上游故障与幂等、未配置提示、SHA 推进重新预览、提交绕过、现有草稿/回执/历史/截止/评分回归。网络模拟测试不能代替真实组织授权和上线验收。
