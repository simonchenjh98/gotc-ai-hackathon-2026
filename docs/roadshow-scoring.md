# 路演评委与 100 分评分

| 使用者 | 入口 | 用途 |
| --- | --- | --- |
| 路演评委 | `/gotc/platform.html#judge-roadshow` | 以名单中的姓名登录，查看本轮队伍、保存或提交本人评分。 |
| 组织方 | `/gotc/platform.html#admin-roadshow` | 配置队伍和评委、核对实时汇总、确认路演成绩。 |
| 组织方 | `/gotc/platform.html#admin` | 在路演设置中开始或关闭本轮评分窗口。 |
| 参赛队伍 | `/gotc/platform.html#team-score` | 成绩确认后，以本队参赛码查看本队结果。 |

## 配置名单与开窗

1. 在路演后台每行填写一位评委的完整姓名，保存后建立本轮评委身份。同名评委应加单位等说明区分，并告知本人完整写法。
2. 从队伍目录勾选实际参赛队伍，保存路演队伍名单。新登记的队伍可在候选目录中查到，需要勾选保存后才出现在评委的选队菜单。
3. 评委在登录开放后，在「邀请码（真实姓名）」输入名单中的完整姓名，点击「验证姓名并登录」。若提示名单未配置或登录尚未开放，由组织方核对名单、身份启用状态及本轮登录时间。
4. 核对队伍名单及至少 3 位已启用的本轮评委后，点击「开始90分钟路演」。首次开放会冻结名单，90 分钟到时停止接收评分，也可提前关闭。评委登录开放与评分开窗独立。重复开始不能为已开始的窗口续时。

## 数值评分

| 维度 | 满分 |
| --- | ---: |
| 问题价值与理解 | 20 |
| 方案与 AI 使用 | 20 |
| 原型完成度 | 20 |
| 测试与改进 | 15 |
| 社会关怀与责任 | 10 |
| 团队协作与表达 | 15 |

六项直接合计 100 分，每项最多一位小数。每位评委对每队保存一份记录，再次正式提交会替换本人原分。每队至少需要 **3 位不同的有效评委正式评分**，取得有效成绩后，取该队全部有效正式评分的均值。草稿、回避和未交均不计入份数或均分。路演不设专项奖提名。

组织方可查看各队份数、回避数和均分。不足 3 份的队伍标为「评分不足」，暂定均分仅供后台核对。评委页面每 2 秒同步名单和窗口，未保存输入会保留。

## 确认成绩与决赛入围

评分关闭或截止后，在路演后台核对有效成绩队伍数，再点击「确认路演成绩」。

| 具备资格且未回收的本轮队伍数 | 允许确认的最低条件 |
| --- | --- |
| 12 队及以上 | 至少 12 队各自取得有效成绩 |
| 不足 12 队 | 至少 1 队取得有效成绩 |

确认后默认按未经显示舍入的均分从高到低同步前 12 队至决赛。有效成绩少于 12 队的小规模轮次同步所有取得有效成绩的队伍。真实均分相同的队伍排名并列，截取名额时按队号排序。若组织方已单独确认当前轮次的入围名单，按该名单及顺序同步。确认记录已失效、决赛名单已锁定且与拟同步名单冲突时，请先核对原因。详见[决赛操作](finals.md)。

全队排名和汇总只在组织方后台显示。确认后，各队可登录查看本队已发布成绩。重新开放、名单或资格等变更可能使原发布失效，组织方需核对当前状态并重新确认。

## 维护

保存私有数据库时应配套保留原 `GOTC_DATA_DIR/roadshow-claim-key`。[备份工具](../ops/backup_event.py)会核验并复制与数据库配套的原密钥。有路演名单历史的数据库如缺少原密钥，应找回对应备份。登录时使用姓名，仍需保留服务端密钥。发布与恢复见[部署手册](../ops/deploy/README.md)。
