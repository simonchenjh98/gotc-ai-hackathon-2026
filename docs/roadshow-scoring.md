# 路演评委与100分评分

## 操作入口

- 路演评委：`/gotc/platform.html#judge-roadshow`
- 路演名单、实时成绩及发布：`/gotc/platform.html#admin-roadshow`
- 公开路演成绩：`/gotc/platform.html#board-roadshow`

名单未配置时，评委入口明确显示待配置，不会让任意姓名注册。组织方收到真实评委名单后，在路演后台按每行一位姓名保存。同名评委需加单位等区分，领取时填写同样的完整名称。名单保存自动创建本轮路演的专属身份，不会自动开放评分。

评委输入完整姓名领取自己的专属邀请码，可复制或填入登录框后点击登录；重复领取会得到同一码，不新建身份。邀请码只在当前页面显示，不保存到浏览器本地存储。管理员手动换码或停用的身份不能通过公开领取覆盖管理操作。

## 计分与同步

六维依次为创意20、社会关怀15、技术呈现20、应用潜力20、AI跨界探索15、开源贡献10，共100分；分数最多一位小数。路演与决赛、原专业评分数据完全独立。

每位本轮评委对每队保存一份评分，正式提交后参与平均分，改分替换原分；草稿不计分，未提交不当0分。回避需明确提交。后台显示有效评分数、回避数及暂定均分，每2秒同步；同步不会覆盖未保存输入。没有路演专项奖提名，也不自动生成晋级名单。

组织方先在原后台的路演设置中选定本轮队伍及评委、开放窗口。首次开放后名单冻结。收齐所有已分配评委对各队的正式评分或回避、且每队至少1份有效评分后，关闭窗口，在路演后台核对并发布。公开看板此时显示最终结果；重新开放、改名单或资格/名称变化会使旧公开结果失效，恢复原值不会自动重新发布。

## 维护注意事项

新增独立数值表保留旧路演评语和全部历史数据。部署不会创建演练队伍或录入虚拟评委，也不自动打开正式比赛窗口。

私有 `GOTC_DATA_DIR/roadshow-claim-key` 与 `event.sqlite3` 必须配套备份与恢复。数据库只保存邀请码哈希和派生参数；缺少原密钥时服务拒绝静默生成不同的邀请码。现有 `scripts/backup_event.py` 只复制SQLite数据库，异机恢复时还应单独以私有权限保存原密钥文件。常规原地部署保留整个data目录，不受影响。密钥、邀请码和测试数据不得放入Git或公共静态目录。
