# 路演评委与100分评分

## 操作入口

- 路演评委：`/gotc/platform.html#judge-roadshow`
- 路演名单、实时成绩及发布：`/gotc/platform.html#admin-roadshow`
- 公开路演成绩：`/gotc/platform.html#board-roadshow`

名单未配置时，评委入口明确显示待配置，不会让任意姓名注册。组织方收到真实评委名单后，在路演后台按每行一位姓名保存。同名评委需加单位等区分，领取时填写同样的完整名称。名单保存自动创建本轮路演的专属身份，不会自动开放评分。

评委输入完整姓名领取自己的专属邀请码，可复制或填入登录框后点击登录；重复领取会得到同一码，不新建身份。邀请码只在当前页面显示，不保存到浏览器本地存储。管理员手动换码或停用的身份不能通过公开领取覆盖管理操作。

## 计分与同步

六维依次为创意20、社会关怀15、技术呈现20、应用潜力20、AI跨界探索15、开源贡献10，共100分；分数最多一位小数。路演与决赛、原专业评分数据完全独立。

每位本轮评委对每队保存一份评分，正式提交后参与平均分，改分替换原分；草稿不计分，未提交不当0分。每队至少获得3位不同评委的正式评分才有效，均分使用该队全部正式评分。回避不计入3份门槛。未满3份标记“评分不足”，不参与排名；后台可查看暂定均分，公开看板不展示其有效均分。后台显示已交份数、回避数及均分，每2秒同步；同步不会覆盖未保存输入。没有路演专项奖提名，也不自动生成晋级名单。

组织方先在原后台的路演设置中选定本轮队伍及评委，再点击“开始90分钟路演”。服务器设置截止时间，到时自动停止接收评分；管理员也可提前关闭。首次开放后名单冻结，当前轮次不能靠重复点击开始延长时间。评分关闭或截止后，只要至少1支队伍满足3份正式评分即可核对发布，其他队伍保留“评分不足”状态。公开看板此时显示最终结果；重新开放、改名单或资格/名称变化会使旧公开结果失效，恢复原值不会自动重新发布。

## 维护注意事项

新增独立数值表保留旧路演评语和全部历史数据。部署不会创建演练队伍或录入虚拟评委，也不自动打开正式比赛窗口。

私有 `GOTC_DATA_DIR/roadshow-claim-key` 与 `event.sqlite3` 必须配套保存。`scripts/backup_event.py` 的 backup/restore 和部署器私有备份现会自动把原密钥复制到目标数据库同目录，验证摘要并使用 0600 权限；不会覆盖已有的不同密钥。数据库中只要有任何路演名单历史（包括已移除身份），缺少原密钥时备份或启动均会失败，不会生成替代码。从未配置过路演名单的旧数据库允许仅数据库恢复，并绑定新密钥。密钥、邀请码和测试数据不得放入 Git 或公共静态目录。
