# 路演评委与100分评分

## 操作入口

- 路演评委：`/gotc/platform.html#judge-roadshow`
- 路演名单、实时成绩及发布：`/gotc/platform.html#admin-roadshow`
- 公开路演成绩：`/gotc/platform.html#board-roadshow`

名单未配置时，评委入口明确显示待配置，不会让任意姓名注册。组织方收到真实评委名单后，在路演后台按每行一位姓名保存。同名评委需加单位等区分，登录时填写同样的完整名称。名单保存自动创建本轮路演的专属身份，不会自动开放评分。

路演后台直接读取“队伍信息”的同一份队伍目录，可选中全部有效队伍或按需勾选，再保存路演队伍名单。保存只调整本轮队伍，不改变已配置的评委和评分开关。新增登记队伍会出现在候选目录中，主办方须在开赛前核对并保存；首次开窗冻结后，不能用重新加载目录覆盖名单或成绩。评委的队伍下拉按编号和名称显示已保存的路演名单，每2秒同步；有未保存输入或提交中请求时保留当前表单，并提示核对更新。

路演邀请码就是评委的真实姓名。评委在唯一的“邀请码（真实姓名）”输入框填写主办方名单中的完整姓名，点击“验证姓名并登录”，匹配后直接进入评分；不需要领取、复制或填写随机码。姓名登录不创建身份，不能让名单外姓名注册。服务端签发现有评委会话Cookie，前端再次核验评委身份与登录标记一致后才进入评分。管理员手动更改凭据或停用的身份不能通过姓名登录覆盖管理操作；后台显示姓名登录资格，不推测首次登录状态。

## 计分与同步

六维依次为创意20、社会关怀15、技术呈现20、应用潜力20、AI跨界探索15、开源贡献10，共100分；分数最多一位小数。路演与决赛、原专业评分数据完全独立。

每位本轮评委对每队保存一份评分，正式提交后参与平均分，改分替换原分；草稿不计分，未提交不当0分。每队至少获得3位不同评委的正式评分才有效，均分使用该队全部正式评分。回避不计入3份门槛。未满3份标记“评分不足”，不参与排名；后台可查看暂定均分，公开看板不展示其有效均分。后台显示已交份数、回避数及均分，每2秒同步；同步不会覆盖未保存输入。没有路演专项奖提名，也不自动生成晋级名单。

组织方先在原后台的路演设置中选定本轮队伍及评委，再点击“开始90分钟路演”。服务器设置截止时间，到时自动停止接收评分；管理员也可提前关闭。首次开放后名单冻结，当前轮次不能靠重复点击开始延长时间。评分关闭或截止后，只要至少1支队伍满足3份正式评分即可核对发布，其他队伍保留“评分不足”状态。公开看板此时显示最终结果；重新开放、改名单或资格/名称变化会使旧公开结果失效，恢复原值不会自动重新发布。

## 维护注意事项

新增独立数值表保留旧路演评语和全部历史数据。部署不会创建演练队伍或录入虚拟评委，也不自动打开正式比赛窗口。

兼容原有路演身份数据仍需将私有 `GOTC_DATA_DIR/roadshow-claim-key` 与 `event.sqlite3` 配套保存。姓名登录页面不展示随机码，也不改变原有私有凭据校验和备份要求。`scripts/backup_event.py` 的 backup/restore 和部署器私有备份现会自动把原密钥复制到目标数据库同目录，验证摘要并使用 0600 权限；不会覆盖已有的不同密钥。数据库中只要有任何路演名单历史（包括已移除身份），缺少原密钥时备份或启动均会失败，不会生成替代码。从未配置过路演名单的旧数据库允许仅数据库恢复，并绑定新密钥。密钥、邀请码和测试数据不得放入 Git 或公共静态目录。
