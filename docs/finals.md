# 决赛评分与专项奖使用说明

## 入口

- 决赛评委：`/gotc/platform.html#judge-finals`
- 决赛后台：`/gotc/platform.html#admin-finals`
- 公开结果：`/gotc/platform.html#board-finals`

这是独立的决赛系统，数据不写入原专业评分或展示/路演评语。部署不会自动将现有队伍列入决赛，也不会自动开放评分或公布成绩。

## 评分和提名

8位评委打开决赛页面，先输入主办方提供的统一决赛邀请码，再选择自己的姓名或席位。邀请码由后端验证，通过后可在当前标签页选择和切换席位；退出验证或凭据到期后需重新输入。验证仅用于决赛，不会登录组织方后台。六维为创意20、社会关怀15、技术呈现20、应用潜力20、AI跨界探索15、开源贡献10，总分100。分数可保留一位小数；总成绩取有效正式评分的平均值，草稿不参与计算，未交不计0分。回避必须明确提交；后台显示有效评分和回避人数，不能把只有部分评委评分的暂定均分当最终结果。

每位评委另外提交一张六奖提名表。每个奖项选择最多一队或明确弃权；同一队可以被提名多个奖项。每奖最多8票，六奖最多48票；改提名替换本人该奖选择，不叠加票数。提名与100分独立统计。

每队最多获得1个专项奖。按下列顺序处理：

1. 最佳创意奖
2. 最具社会关怀奖
3. 最佳技术呈现奖
4. 最具应用潜力奖
5. 最佳 AI 跨界探索奖
6. 最佳开源贡献奖

每个奖项排除已获得前面奖项的队伍后，剩余候选最高正票获奖；最高票并列时共同获奖。没有正票或候选均已获得前面的奖项时，该奖空缺。后台可展开每奖的候选名单，看到队伍编号、队名、原始票数、原始领先者、顺延说明及建议获奖者。

例如：1、2队各4票并列创意奖；技术奖1队5票、4队3票，则1队保留创意奖，技术奖顺延给4队，原始5票和3票仍显示。

## 管理员流程

1. “决赛后台”直接读取队伍信息的同一份候选目录。主办方勾选实际入围队伍并保存；新增登记队伍不会自动进入决赛。评委的评分和提名下拉只显示已保存的入围名单，每2秒同步名单及评分窗口，有未保存输入时保留表单并提示核对更新。
2. 选择8个有效评委席位，或点击“建立8个决赛评委席位”。评委直接打开决赛链接，在页面选择自己的姓名或席位；系统不会生成或要求输入评委邀请码。
3. 保存决赛名单并核对；首次开放后名单锁定，避免覆盖已有评审。使用前应先完成独立演练。
4. 开放评分与提名。后台每2秒检查一次最新统计，网络超时显示同步故障，不把旧数据伪装成已更新；隐藏标签页暂停轮询。
5. 收齐每队8位评委的正式评分或明确回避（每队至少1份有效数值评分），并收齐8份正式提名表（允许整张弃权）。关闭评分与提名。
6. 展开六个奖项核对候选和顺延建议，点击“确认六项专项奖归属”。该动作确认整份建议名单，不修改原始票数。
7. 重新载入设置，勾选“发布最终成绩和获奖队伍”并保存。公开结果页此时才显示最终成绩与获奖队伍；并列获奖队长均可上台领奖。

若需改分或改提名，重新开放会撤销发布和获奖确认；修改后须再次关闭、确认并发布。取消队伍资格、停用评委，以及修改入围队伍的队号、队名、作品名或评委姓名，都会使已确认/已发布结果失效；恢复原值不会自动恢复公开，必须再次核验。

## 保存与冲突

评分与提名各有独立编辑版本。多个页面同时修改时旧页面返回409，保留当前输入并要求核对最新数据；不会自动重发，也不会覆盖其他评委的内容。窗口关闭后所有评分/提名写入均拒绝。决赛评分和提名以当前页面选择的评委席位归属，每个请求固定携带该席位，不借用组织方或其他页面的登录Cookie。席位选择不承担身份验证；管理员操作仍需组织方登录并核对页面身份。

## 升级与回退

新增 `server/finals.py`、`platform-finals.js`、`platform-finals.css`；后两者必须同时加入服务和安装器静态白名单。首次升级生成私有 `before-finals-*.sqlite3` 备份，在事务内创建独立表和资格变化版本触发器。已有作品、原评分、评语和投票保留。

生产部署前运行 `node --test tests/*.test.mjs`、`python -B -m unittest discover -s server -q`、`python -B scripts/check_site.py`，并完成安装器/发布安全检查。不得把本地 `.qa` 演练数据库、截图中的演练队伍或测试凭据导入正式库。
